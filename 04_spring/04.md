<h2>👣 Passo 04 - O arquivo pom.xml</h2>



O **POM** (**Project Object Model** - "Projeto Modelo do Objeto"), é um arquivo **XML** (**eXtensible Markup Language**), que dentro do contexto de um projeto Maven, é o arquivo mais importante do projeto. O POM guarda todas as informações básicas de um projeto Maven, bem como as diretivas de como o artefato (resultado) final deste projeto deve ser construído. 

Dentro do POM colocamos as informações de todas as Dependências (Bibliotecas), que o nosso projeto necessita para funcionar e que o Maven se encarregará de efetuar o download e inserir no **Build Path** (Caminho para as Bibliotecas utilizadas pelo compilador Java para construir o projeto final) e **Classpath** (Caminho para os pacotes utilizados no projeto durante o desenvolvimento das Classes, ou seja, as instruções Import inseridas no inicio das nossas Classes).

O Maven irá buscar por essas Dependências em locais chamados **Repositórios**. Existem basicamente dois Repositórios: 

- O **Repositório Local**, que está localizado na pasta **.m2/repository**, onde o Maven baixa todas as Bibliotecas utilizadas nos seus projetos. 
- O **Repositório Remoto Maven Repository**, que é o Repositório padrão e oficial do Maven, onde ficam armazenadas as Dependências Oficiais do Spring.

| <img src="https://i.imgur.com/hOgWvSc.png" title="source: imgur.com" width="80px"/> | <div align="left"> **ATENÇÃO:** *A pasta .m2 geralmente está localizada no seu computador em: C:\Users\seu usuario\\.m2\repository* </div> |
| ------------------------------------------------------------ | ------------------------------------------------------------ |

Ao adicionar uma Dependência no seu Projeto Spring, o Maven primeiro realiza a busca no Repositório Local. Se a Dependência não for encontrada, o Maven irá buscar as Dependências no Repositório Remoto e fará o download no Repositório Local. Após o download, o Maven disponibilizará esta Dependência no Repositório Local para todos os seus Projetos Spring. Caso você necessite utilizar a mesma Dependência em outro projeto não será necessário realizar o download novamente.

<h3>4.1. Estrutura básica do arquivo pom.xml</h3>



Vamos analisar o arquivo pom.xml gerado em nosso Projeto Blog Pessoal:

**Parte 01:** Esse trecho representa o início do arquivo `pom.xml`, responsável por configurar um projeto Maven. 

- A declaração `<?xml version="1.0" encoding="UTF-8"?>` informa a versão do XML e a codificação utilizada. 
- A tag `<project>` define o elemento principal do documento e especifica os namespaces (`xmlns` e `xmlns:xsi`) que identificam os padrões XML adotados pelo Maven. 
- O atributo `xsi:schemaLocation` indica a localização do esquema oficial usado para validar a estrutura do arquivo. 
- A tag `<modelVersion>4.0.0</modelVersion>` define a versão do modelo POM utilizada pelo Maven, sendo a versão `4.0.0` a adotada atualmente pela maioria dos projetos Java e Spring Boot.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
	xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
	xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
	<modelVersion>4.0.0</modelVersion>
```

**Parte 02:** Define o projeto pai (*parent*) da aplicação Maven. Nesse caso, o projeto herda as configurações do `spring-boot-starter-parent`, fornecido pelo Spring Boot, que disponibiliza versões compatíveis das dependências, configurações padrão de compilação e plugins necessários para a construção e execução da aplicação. 

- A tag `<groupId>` identifica a organização responsável pelo artefato
- A tag `<artifactId>` especifica o nome do projeto pai
- A tag `<version>` define a versão do Spring Boot utilizada. 
- A tag `<relativePath />` vazia indica que o Maven deve procurar o projeto pai nos repositórios configurados, como o Maven Repository, em vez de buscar em um arquivo local. 
- O comentário `<!-- lookup parent from repository -->` reforça esse comportamento.

```xml
	<parent>
		<groupId>org.springframework.boot</groupId>
		<artifactId>spring-boot-starter-parent</artifactId>
		<version>4.1.0</version>
		<relativePath /> 
    	<!-- lookup parent from repository -->
	</parent>
```
**Parte 03:** Contém as informações de identificação do projeto Maven. 

- A tag `<groupId>` define o grupo ou a organização responsável pelo projeto, funcionando como um identificador único, neste caso `com.generation`. 
- A tag `<artifactId>` especifica o nome do artefato gerado, que será `blogpessoal`. 
- A tag `<version>` indica a versão atual do projeto, sendo que o sufixo `SNAPSHOT` representa uma versão em desenvolvimento, ainda sujeita a alterações. 
- A tag `<name>` define um nome amigável para o projeto
- A tag `<description>` fornece uma breve descrição de sua finalidade, neste caso, um sistema chamado "Projeto Blog Pessoal". 

Juntas, essas informações identificam a aplicação e são utilizadas pelo Maven durante a compilação, o empacotamento e a publicação do projeto.

```xml
	<groupId>com.generation</groupId>
	<artifactId>blogpessoal</artifactId>
	<version>0.0.1-SNAPSHOT</version>
	<name>blogpessoal</name>
	<description>Projeto Blog Pessoal</description>
```

**Parte 04:** Contém um conjunto de tags xml que armazenam os metadados do projeto. Elas não influenciam diretamente a execução da aplicação Spring, mas são úteis para documentação, publicação em repositórios Maven e identificação do projeto.

### Tags de Metadados do Projeto

| Tag                         | Descrição                                                    |
| --------------------------- | ------------------------------------------------------------ |
| `<url>`                     | URL principal do projeto, geralmente o repositório GitHub ou a página oficial. |
| `<licenses>`                | Lista das licenças utilizadas pelo projeto.                  |
| `<license>`                 | Define uma licença específica (MIT, Apache 2.0, GPL etc.).   |
| `<developers>`              | Lista dos desenvolvedores responsáveis pelo projeto.         |
| `<developer>`               | Informações de um desenvolvedor, como nome e e-mail.         |
| `<scm>`                     | Configurações do sistema de controle de versão (Git, SVN etc.). |
| `<connection>`              | URL de conexão pública com o repositório.                    |
| `<developerConnection>`     | URL de conexão para desenvolvedores com permissão de escrita. |
| `<tag>`                     | Tag ou versão do código-fonte associada ao projeto.          |
| `<url>` (dentro de `<scm>`) | Endereço do repositório no navegador.                        |

Como não iremos publicar o projeto no **Maven Repository**, vamos deixar como estão.

```xml
	<url />
	<licenses>
		<license />
	</licenses>
	<developers>
		<developer />
	</developers>
	<scm>
		<connection />
		<developerConnection />
		<tag />
		<url />
	</scm>
```

**Parte 05:** Informa a versão do Java (`java.version`), que foi selecionada no **Spring Initializr** durante a construção do projeto.


```xml
	<properties>
		<java.version>17</java.version>
```

**Parte 07:** A seção `<build>` define as configurações relacionadas ao processo de construção (*build*) da aplicação. 

- A tag `<plugins>` agrupa os plugins utilizados pelo Maven para executar tarefas específicas durante a compilação, os testes e o empacotamento do projeto. Nesse exemplo, o plugin `spring-boot-maven-plugin`, fornecido pelo Spring Boot, é responsável por gerar o arquivo executável da aplicação (`.jar` ou `.war`), além de disponibilizar comandos que facilitam o desenvolvimento, como a execução da aplicação diretamente pelo Maven por meio do comando `mvn spring-boot:run`. Esse plugin também gerencia a inclusão de todas as dependências necessárias no pacote final, permitindo que a aplicação seja executada de forma independente em qualquer ambiente que possua a Máquina Virtual Java (JVM). A tag `</project>` indica o encerramento do arquivo `pom.xml`.

```xml
	<build>
		<plugins>
			<plugin>
				<groupId>org.springframework.boot</groupId>
				<artifactId>spring-boot-maven-plugin</artifactId>
			</plugin>
		</plugins>
	</build>

</project>
```

O arquivo `pom.xml` é um arquivo dinâmico que evolui conforme o projeto cresce. Durante o desenvolvimento da aplicação, novas dependências, plugins e configurações podem ser adicionados de acordo com as novas funcionalidades implementadas, necessidades de integração, ferramentas utilizadas e requisitos do sistema. Dessa forma, o Maven utiliza esse arquivo como fonte central de configuração para gerenciar bibliotecas, realizar o processo de compilação, executar testes e gerar o pacote final da aplicação.

<h3>Configurações da Conexão com o Banco de dados</h3>

| Item                                                     | Descrição                                                    |
| -------------------------------------------------------- | ------------------------------------------------------------ |
| **spring.jpa.hibernate.ddl-auto**                        | Define como o JPA irá inicializar o banco de dados. **update** ⇨ O modelo de objeto criado com base nas anotações nas classes `Model` é comparado com o esquema existente, e o Hibernate atualiza o esquema conforme as diferenças encontradas. | **spring.jpa.open-in-view**                              | Define se o *Open Session in View* do JPA estará ativo. Quando habilitada (`true`), a sessão com o banco de dados permanece aberta durante toda a requisição HTTP, permitindo o carregamento *lazy* de relacionamentos mesmo após a execução do método no repositório. |

<h2>Observações importantes:</h2>

- O Nome do banco de dados deve seguir o padrão **db_nome-do-banco**. O prefixo **db** indica que se trata de um Database (Banco de dados). O nome do banco é recomendado que seja **o mesmo do projeto** (blogpessoal), em **letras minúsculas**, **sem espaços em branco ou caracteres especiais e acentos**. Para separar as palavras em um nome composto, utilize o _ (underline). **Exemplo:** db_blog_pessoal.

- O endereço **localhost** é o endereço local, ou seja, o seu próprio computador. Quando a aplicação estiver na nuvem, o endereço do Banco de dados será alterado para um endereço remoto.

- Para fins de aprendizagem, estamos utilizando no SGBD MySQL o usuário **root**. Vale ressaltar que no mercado de trabalho, uma aplicação em produção, jamais utilizará o usuário root, por se tratar do usuário administrador do SGBD, que tem plenos poderes sobre o Servidor. Em geral, o DBA (Database Administrator), cria um usuário apenas com os direitos de acesso que a aplicação irá precisar.

- Durante o Desenvolvimento da aplicação, você pode manter a opção: **spring.jpa.show-sql** habilitada (true). Em produção ela deve ser desabilitada.

- O **Hibernate** é um framework para o mapeamento Objeto-Relacional escrito na linguagem Java, cujo objetivo é diminuir a complexidade entre os programas Java, baseado no modelo Orientado a Objetos, que precisam trabalhar com um banco de dados do modelo Relacional (presente na maioria dos SGBD's). Em especial, no desenvolvimento de consultas e atualizações dos dados.

- **Open Session In View** é a "sessão" (conexão), que fica aberta até o final da execução de uma consulta ao Banco de dados, via requisição http, que possibilita que os dados do Relacionamento entre entidades (tabelas), sejam recuperados a qualquer momento. Esta opção foi desabilitada por questões de performance da aplicação.

- A configuração do **fuso-horário** no **Servidor de Banco de dados** e no **Servidor da aplicação** são itens essenciais para evitar que a data e a hora incorretas sejam persistidas no Banco de dados, especialmente em Atributos do tipo Timestamp, que obtém a data e a hora do Servidor.

<h2 id="anexo2">Anexo II - Modos de inicialização do Banco de dados</h2>

| Forma           | Descrição                                                    |
| --------------- | ------------------------------------------------------------ |
| **update**      | O modelo de objeto criado com base nos mapeamentos (Anotações na Classe Model), é comparado com o esquema existente, e então o Hibernate atualiza o esquema de acordo com as diferenças. Ele nunca exclui as tabelas ou colunas existentes, mesmo que não sejam mais exigidas pelo aplicativo. Nesta opção os dados persistidos não são apagados. |
| **create**      | O Hibernate primeiro elimina todas as tabelas existentes no Banco de dados e então cria novas tabelas. Com esta opção todos os seus dados serão perdidos a cada inicialização do projeto. |
| **create-drop** | Semelhante ao create, com a adição de que o Hibernate irá descartar o banco de dados depois que todas as operações forem concluídas. Esta opção é normalmente utilizada para testes de unidade. |
| **validate**    | Verifica apenas se a estrutura do Banco de dados corresponde às entidades definidas na **Classe Model**. Se o esquema não corresponder, a inicialização do aplicativo lançará um erro (Exception). |
| **none**        | Desativa a inicialização do Banco de dados.                  |

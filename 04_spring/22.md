<h1>Teste de Software com JUnit 5 - Configurando o Ambiente de testes</h1>



Este conteúdo apresenta, de forma prática e objetiva, os passos necessários para configurar o ambiente de testes em um projeto **Spring Boot**, utilizando **JUnit 5** e o banco de dados em memória **H2**.

<br />


<h2>👣 Passo 01 - Configurações das Dependências</h2>



Neste passo, vamos **ajustar as dependências de teste**, que forma adicionadas automaticamente na criação do projeto e **incluir** algumas outras dependências que serão utilizadas nos testes.

<br />

<h3>1. Configurar as Dependências de teste no arquivo pom.xml</h3>



A partir do **Spring Boot 4**, a antiga dependência agregadora **`spring-boot-starter-test`** deixou de ser adicionada automaticamente pelo **Spring Initializr**, e o suporte a testes passou a ser organizado em dependências menores e específicas.

Dessa forma, o projeto recebe apenas os módulos de teste necessários para cada recurso utilizado, como **`spring-boot-starter-data-jpa-test`** para testes relacionados à persistência de dados, **`spring-boot-starter-webmvc-test`** para testes de APIs Web MVC e **`spring-boot-starter-validation-test`** para validação de informações. Essa abordagem torna o gerenciamento das dependências mais específico, reduzindo a inclusão de bibliotecas que não serão utilizadas no projeto.

Além disso, algumas dessas dependências de teste incluem, por padrão, a biblioteca **Mockito**, utilizada para criação de objetos simulados (*mocks*) durante testes unitários.

Como o **Mockito** não será utilizado neste projeto, precisamos remover a dependência **`mockito-core`** de todas as dependências de teste adicionadas pelo Spring Boot. Essa remoção é realizada por meio da configuração da tag **`<exclusions>`** no arquivo `pom.xml`, informando explicitamente qual biblioteca deve ser desconsiderada.

Dessa forma, evitamos o carregamento desnecessário de recursos que não serão utilizados, reduzimos possíveis conflitos entre bibliotecas e eliminamos os avisos relacionados ao carregamento de **Java Agent** exibidos durante a execução dos testes. Com isso, o ambiente de testes fica mais limpo, organizado e alinhado com as ferramentas realmente utilizadas na aplicação.

No arquivo `pom.xml`, **localize** as dependências de teste abaixo, no final da seção **`<dependencies>`**:

```xml
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-data-jpa-test</artifactId>
			<scope>test</scope>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-validation-test</artifactId>
			<scope>test</scope>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-webmvc-test</artifactId>
			<scope>test</scope>
		</dependency>
```

E **Substitua pelo trecho de código abaixo:**

```xml
		<!-- Dependências - Testes Automatizados -->
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-data-jpa-test</artifactId>
			<scope>test</scope>
			<exclusions>
				<exclusion>
					<groupId>org.mockito</groupId>
					<artifactId>mockito-core</artifactId>
				</exclusion>
			</exclusions>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-validation-test</artifactId>
			<scope>test</scope>
			<exclusions>
				<exclusion>
					<groupId>org.mockito</groupId>
					<artifactId>mockito-core</artifactId>
				</exclusion>
			</exclusions>
		</dependency>
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-webmvc-test</artifactId>
			<scope>test</scope>
			<exclusions>
				<exclusion>
					<groupId>org.mockito</groupId>
					<artifactId>mockito-core</artifactId>
				</exclusion>
			</exclusions>
		</dependency>
```
A tag **`<exclusions>`** é utilizada no arquivo `pom.xml` para informar ao Maven que uma determinada dependência transitiva não deve ser incluída no projeto. Uma dependência transitiva é uma biblioteca que vem automaticamente junto com outra dependência adicionada manualmente. 

Dentro da tag **`<exclusions>`**, utilizamos a tag **`<exclusion>`** para especificar exatamente qual biblioteca deve ser removida, informando seu **`groupId`** e **`artifactId`**. Essa configuração permite maior controle sobre as bibliotecas carregadas pela aplicação, evitando dependências desnecessárias, possíveis conflitos de versões ou recursos que não serão utilizados no projeto.

<br />

<h3>2. Adicionar as Dependências restclient e resttestclient no arquivo pom.xml</h3>



As dependências **`spring-boot-starter-restclient`** e **`spring-boot-resttestclient`** fazem parte do suporte de testes do Spring Boot para realizar chamadas HTTP durante a validação da aplicação. Elas são utilizadas principalmente em testes de integração, permitindo que o código de teste envie requisições para os endpoints da API e verifique as respostas retornadas pelo servidor.

A dependência **`spring-boot-resttestclient`** disponibiliza a classe **`TestRestTemplate`**, um cliente HTTP criado especificamente para testes de aplicações Spring Boot. Com ela, é possível simular requisições como **GET**, **POST**, **PUT** e **DELETE**, enviando dados para a API e validando informações como código de resposta HTTP, cabeçalhos e corpo da resposta. Essa abordagem permite testar a aplicação de forma semelhante ao comportamento de um cliente externo consumindo a API.

Já a dependência **`spring-boot-starter-restclient`** fornece a infraestrutura necessária para o funcionamento do cliente HTTP utilizado pelo `TestRestTemplate`. Ela disponibiliza as implementações e configurações necessárias para realizar as chamadas HTTP durante os testes. Dessa forma, essas dependências trabalham em conjunto para permitir testes de integração mais próximos do ambiente real, garantindo que os recursos da API estejam funcionando corretamente.

Para utilizar as dependências **`spring-boot-starter-restclient`** e **`spring-boot-resttestclient`** no projeto Spring Boot, é necessário adicioná-las ao arquivo `pom.xml` dentro da seção **`<dependencies>`**.

Adicione o bloco de código abaixo no arquivo `pom.xml`:

```xml
		<!-- Disponibiliza a classe TestRestTemplate -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-resttestclient</artifactId>
            <scope>test</scope>
        </dependency>

        <!-- Fornece a infraestrutura utilizada pelo TestRestTemplate -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-restclient</artifactId>
            <scope>test</scope>
        </dependency>
```

Posicione essas dependências **antes das três dependências de teste já existentes** para manter a organização e facilitar a leitura do arquivo `pom.xml`.

<br />

<h3>3. Adicionar a Dependência do Banco de Dados H2 no arquivo pom.xml</h3>



Para utilizar o banco de dados **H2** durante a execução dos testes do projeto, é necessário adicionar sua dependência no arquivo `pom.xml`. 

O **H2** é um banco de dados em memória utilizado principalmente em testes automatizados, permitindo executar a aplicação em um ambiente isolado sem a necessidade de utilizar o banco de dados principal do projeto, como o MySQL.

Adicione o seguinte bloco de código:

```xml
<!-- Dependência do Banco de dados H2 -->
<dependency>
	<groupId>com.h2database</groupId>
	<artifactId>h2</artifactId>
	<scope>test</scope>
</dependency>
```

Insira esta dependência **logo abaixo da dependência do MySQL** para manter a organização e facilitar a identificação dos bancos de dados utilizados pelo projeto no arquivo `pom.xml`.

💾 **Salve as alterações antes de prosseguir ( File 🡪 Save All ) e aguarde o STS efetuar o download das novas Dependências!**

<h2>👣 Passo 02 - Criar a Source Folder src/test/resources</h2>



Agora vamos configurar a conexão com o banco de dados **H2** para que os testes sejam executados em um ambiente separado, sem interferir no banco de dados principal utilizado pela aplicação.

Como o projeto ainda não possui a pasta **`resources`** dentro da *source folder* de testes (**`src/test`**), será necessário criá-la manualmente. Em seguida, adicionaremos um novo arquivo **`application.properties`** nessa pasta para definir as configurações específicas do ambiente de testes, como a conexão com o banco H2 e demais propriedades necessárias para a execução dos testes automatizados. Dessa forma, a aplicação utilizará configurações diferentes durante os testes, mantendo os dados de desenvolvimento e produção protegidos.

<br />

> [!IMPORTANT]
>
> A configuração será feita **somente** no diretório de testes (`src/test/resources`), **garantindo que o H2 seja utilizado apenas durante a execução dos testes automatizados**.

<br />

1) No lado esquerdo superior, na Guia **Package Explorer**, clique sobre a pasta do projeto com o botão direito do mouse e clique na opção **New 🡪 Source folder**

2) Em **Source Folder**, no item **Folder name**, informe o caminho como mostra a figura abaixo (**src/test/resources**), e clique em **Finish**:

<div align="center"><img src="https://i.imgur.com/bHilbvh.png" title="source: imgur.com" /></div>

<h2>👣 Passo 03 - Configurar o Banco de dados H2</h2>



Após criarmos a Source Folder **src/test/resources**, vamos criar o arquivo **application.properties**, onde vamos adicionar as configurações necessárias para conectar com o Banco de dados H2:

1. No lado esquerdo superior, na Guia **Package explorer**, na Source Folder **src/test/resources**, clique com o botão direito do mouse e clique na opção **New 🡪 File**.
2. No item **File name**, digite o nome do arquivo (**application.properties**) e clique em **Finish**. 

<div align="center"><img src="https://i.imgur.com/VSZCPTR.png" title="source: imgur.com" /></div>

3. Veja o arquivo criado na  **Package Explorer**:

<div align="center"><img src="https://i.imgur.com/vpbrBCc.png" title="source: imgur.com" /></div>

4. Insira no arquivo **application.properties** criado em **src/test/resources** o código abaixo, para configurar o Banco de dados H2:

```properties
spring.datasource.url=jdbc:h2:mem:test;MODE=MySQL
spring.datasource.driver-class-name=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=sa
```
<br />

| Linha                                   | Descrição                                                    |
| --------------------------------------- | ------------------------------------------------------------ |
| **spring.datasource.url**               | Informa a URL de conexão com o banco de dados. Aqui usamos o **H2** no modo **memória** (`mem:test`), o que significa que o banco só existe enquanto a aplicação estiver rodando. O parâmetro `MODE=MySQL` faz o H2 imitar o MySQL, facilitando testes se você usa MySQL em produção. |
| **spring.datasource.driver-class-name** | Indica qual **driver JDBC** será usado para conectar ao banco. No caso do H2, é o `org.h2.Driver`. |
| **spring.datasource.username**          | Define o **usuário** de acesso ao banco. `sa` é o usuário padrão do H2. |
| **spring.datasource.password**          | Define a **senha** do usuário. Também é `sa` por padrão no H2. Em ambientes reais, use senhas mais seguras. |

<br />

💾 **Salve as alterações antes de prosseguir ( File 🡪 Save All )!**

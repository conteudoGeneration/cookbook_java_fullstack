<h2>1. Variáveis e Constantes</h2>



A linguagem JavaScript possui diversos tipos de dados. No entanto, esses tipos **não são definidos de forma explícita no momento da declaração**, pois o JavaScript **não possui tipagem estática**.

Em vez disso, a linguagem adota **tipagem dinâmica**, o que significa que o tipo de uma variável é **inferido automaticamente a partir do valor atribuído**. Além disso, esse tipo **pode ser alterado em tempo de execução**, caso um novo valor de tipo diferente seja atribuído à mesma variável.

<br />

<h3>1.1. Tipos de dados em JavaScript</h3>



Veja na imagem abaixo os tipos de dados da Linguagem JavaScript:

<div align="center"><img src="https://i.imgur.com/7ThmNwn.png" title="source: imgur.com" /></div>

<br />

No JavaScript, **tipos primitivos** são valores simples e imutáveis, ou seja, não podem ser alterados após a sua criação. Quando um valor primitivo é atribuído a uma variável, o que se armazena é o **valor em si**, e não uma referência. Por isso, ao copiar uma variável primitiva para outra, cada uma passa a possuir seu próprio valor independente.

Já os **objetos** representam estruturas mais complexas e mutáveis, capazes de agrupar múltiplos valores e comportamentos em uma única entidade. Diferentemente dos tipos primitivos, ao atribuir um objeto a uma variável, o que se armazena é uma **referência para o objeto na memória**. Assim, alterações feitas por meio de uma variável refletem em todas as outras que apontam para o mesmo objeto, característica fundamental para o gerenciamento de dados mais elaborados na linguagem.

<h4>1.1.1. Tipos Primitivos</h4>



| Tipo          | Descrição                                                    |
| ------------- | ------------------------------------------------------------ |
| **number**    | O JavaScript **não faz distinção entre números inteiros e números de ponto flutuante**. Todos os valores numéricos são representados pelo tipo **number**, seguindo o padrão IEEE 754, sendo tratados internamente como números de ponto flutuante. |
| **string**    | Uma **string** é uma **sequência ordenada e imutável de caracteres**, utilizada para representar textos. Uma vez criada, uma string não pode ser alterada, apenas substituída por outra. |

| **null**      | **null** é um valor especial que representa **a ausência intencional de um valor**. Geralmente é atribuído explicitamente para indicar que uma variável não aponta para nenhum objeto ou valor válido. |
| **undefined** | **undefined** representa um valor **não definido**. É atribuído automaticamente a variáveis declaradas, mas não inicializadas, retornado ao acessar propriedades inexistentes de objetos ou posições inválidas de arrays, além de ser o valor retornado por funções sem `return` explícito. |

👉 **Valores especiais do tipo Number**

O tipo **`number`** possui **valores especiais**, utilizados para representar **resultados inválidos ou infinitos** em operações numéricas. Esses valores fazem parte da especificação da linguagem e são amplamente utilizados em cálculos e validações, conforme apresentado na tabela a seguir:

| Valor especial | Descrição                                                    |
| -------------- | ------------------------------------------------------------ |
| **NaN**        | **NaN** (*Not-a-Number*) é uma propriedade do **objeto global** e representa um resultado numérico inválido. Ele é retornado quando uma operação matemática falha ou quando se tenta converter para número um valor que não pode ser interpretado como tal, como uma string sem representação numérica válida. Diferentemente de algumas linguagens que lançam erro de divisão por zero, o JavaScript retorna `Infinity`. |

>
> - Tanto `NaN` quanto `Infinity` pertencem ao tipo **`number`**.
> - `NaN` é o **único valor em JavaScript que não é igual a ele mesmo** (`NaN !== NaN`).
> - O JavaScript também possui o valor **`-Infinity`**, que representa o infinito negativo.

<h3>1.2. Declaração de Variáveis</h3>



As variáveis em JavaScript podem ser declaradas utilizando as palavras-chave **`var`** ou **`let`**, seguidas de um identificador que representa o nome da variável.

**Sintaxe:**

**Sem atribuição de valor**

```javascript
var identificador_da_variável;
let identificador_da_variável;
```

Quando uma variável é declarada com **`var`** ou **`let`** sem a atribuição de um valor inicial, ela passa a existir no escopo correspondente, porém seu valor inicial será **`undefined`** até que um valor seja explicitamente atribuído.

<br />

**Com atribuição de valor**

```js
var identificador_da_variável = [valor];
let identificador_da_variável = [valor];
```

Nesse caso, além da declaração, a variável já recebe um valor inicial, e o **tipo da variável é inferido automaticamente** com base nesse valor atribuído.

É importante destacar que **não existe declaração explícita de tipo** em variáveis JavaScript. A linguagem possui **tipagem dinâmica**, o que permite que uma variável armazene valores de diferentes tipos ao longo da execução do programa.

Após a declaração, o uso do ponto e vírgula (`;`) é **opcional**, pois o JavaScript possui um mecanismo chamado *Automatic Semicolon Insertion (ASI)*. Ainda assim, seu uso é recomendado para manter clareza e consistência no código. Também é possível declarar **múltiplas variáveis na mesma linha**, separando-as por vírgula, prática comum em diversas linguagens de programação.

<br />

```js
let nome = "Generation";

console.log("Nome:", nome);
```

<h3>1.3.  Qual é a diferença entre o var e o let?</h3>



Antes de entendermos a diferença entre **`var`** e **`let`**, é importante relembrar o conceito de **escopo**.

O **escopo** de uma variável corresponde à região do código-fonte onde essa variável foi declarada e, consequentemente, onde ela pode ser acessada. Na maioria das linguagens de programação, o escopo é delimitado por um par de chaves (**`{ }`**), que define blocos de código como funções, estruturas condicionais e laços de repetição.

Quando uma variável é declarada **dentro de um bloco de código** — como uma estrutura condicional, um laço de repetição ou uma função — dizemos que ela possui **escopo local**. Nesse caso, a variável só pode ser acessada dentro do bloco onde foi declarada. Por outro lado, quando uma variável é declarada **fora de qualquer bloco**, ela possui **escopo global**, podendo ser acessada em qualquer parte do código.

Entretanto, o JavaScript possui um comportamento particular em relação ao escopo. **Diferentemente da maioria das linguagens de programação**, ele **não utiliza blocos delimitados por chaves para definir o escopo global**. As chaves são usadas apenas para definir **escopos locais**, enquanto o escopo global é determinado pelo contexto de execução do script (arquivo ou ambiente). Esse comportamento fica mais evidente ao comparar trechos de código em Java e JavaScript, especialmente no uso de variáveis declaradas dentro de blocos condicionais ou de repetição.

**Classe Java:**

```java
public class HelloWorld {
    
    // Escopo Global
    
    public static void main(String[] args) {
        // Escopo Local;
    }
}
```

Observe, na classe Java, que a própria classe é delimitada pelo **primeiro par de chaves**, o qual define o **escopo da classe** (frequentemente tratado como o escopo mais externo do código). O **segundo par de chaves** delimita o método **`main()`**, que é o método principal da aplicação e define um **escopo local** específico para as variáveis declaradas dentro dele.

Caso sejam criados outros métodos dentro da classe, **cada método será delimitado por seu próprio par de chaves**, possuindo assim um **escopo local independente**. Dessa forma, variáveis declaradas dentro de um método não podem ser acessadas diretamente por outros métodos, reforçando o conceito de encapsulamento e organização do código na linguagem Java.

<br />

**Script JavaScript:**

```javascript
// Escopo Global

if( condição ){
    // Escopo Local
}

function somar(num1, num2){
    // Escopo Local
}

// Escopo Global
```

No caso de um **script JavaScript**, blocos como o `if` e a função `somar` são delimitados por pares de chaves. No entanto, o script como um todo **não possui um par de chaves que delimite explicitamente seu início e fim**. De forma geral, **tudo o que é declarado fora de um bloco de código pertence ao escopo global**, enquanto **tudo o que é declarado dentro de um bloco pertence a um escopo local**.

Quando declaramos uma variável utilizando a palavra reservada **`var`**, o JavaScript a interpreta como uma **variável de escopo de função**, independentemente de onde ela foi declarada — no início, no meio ou no final do script, dentro ou fora de um bloco condicional. Isso faz com que a variável se torne acessível em todo o contexto da função (ou do script, caso não esteja dentro de uma função), o que pode gerar **comportamentos inesperados e difíceis de rastrear**.

> ### Por que isso acontece?
>
> Esse comportamento ocorre devido ao conceito de **hoisting**. 
>
> No JavaScript, as declarações de variáveis feitas com **`var`** são **elevadas (içadas)** para o topo do seu **contexto de execução** antes da execução do código. 
>
> Na prática, quando uma variável é declarada com `var` dentro de um bloco de código, sua **declaração** é movida para o topo do escopo da função ou do script, como se fosse global naquele contexto. Por esse motivo, a variável pode ser acessada em diferentes pontos do código, inclusive antes de sua declaração explícita.

Ao declarar uma variável com a palavra reservada **`let`**, o JavaScript segue a regra geral de escopo:

- **Escopo local**, quando a variável é declarada dentro de um bloco de código (como `if`, `for`, `while` ou `function`), ficando acessível apenas dentro desse bloco;
- **Escopo global**, quando a variável é declarada fora de qualquer bloco de código, tornando-se acessível em todo o script.

> ### Hoisting com `let`
>
> Variáveis declaradas com **`let`** também passam por hoisting, porém com uma diferença fundamental: **elas não podem ser acessadas antes da sua declaração**. 
>
> Quando declaradas dentro de um bloco, permanecem restritas a esse bloco e ficam em uma região chamada de *Temporal Dead Zone (TDZ)* até o momento da declaração. 
>
> Esse comportamento evita acessos indevidos e torna o código **mais previsível e seguro**, sendo uma das principais vantagens do uso de `let` em relação ao `var`.

<h3>1.5. Declaração de Constantes</h3>



No JavaScript, a declaração de uma **constante** é semelhante à declaração de uma variável, porém possui **restrições importantes**. 

Para declarar uma constante, utiliza-se a palavra-chave **`const`** antes do identificador, sendo **obrigatória a atribuição de um valor no momento da declaração**. Não é permitido declarar uma constante sem um valor inicial.

**Sintaxe:**

```js
const identificador_da_constante = [valor];
```

Uma constante, diferentemente de variáveis declaradas com **`let`** ou **`var`**, **não pode ser redeclarada nem reatribuída** após sua criação. Isso significa que o identificador sempre apontará para o mesmo valor ou referência ao longo da execução do programa.

<br />

<div align="left"><img src="https://i.imgur.com/r9lrbPG.png" title="source: imgur.com" width="30px"/> <a href="https://developer.mozilla.org/pt-BR/docs/Web/JavaScript/Reference/Statements/const" target="_blank"><b>Documentação: Constantes</b></a></div>

<br />

## <img src="https://i.imgur.com/zCTwZAz.png" title="source: imgur.com" width="3%"/>**Exemplo 04 - Declaração de  Constantes**

```js
const estado = "São Paulo";
console.log("Estado:", estado);
```

*Uma constante não pode ter o seu valor alterado por atribuição em tempo de execução.* 

```js
estado = "Rio de Janeiro";
```

A ação acima geraria um erro: 

```bash
TypeError: Assignment to constant variable.
```

Indicando que não é possível atribuir um valor para uma **const**.

<br />

> [!IMPORTANT]
>
> No caso de valores **primitivos**, o valor não pode ser alterado. 
>
> Já quando a constante armazena um **objeto ou array**, a referência não pode ser modificada, mas **os dados internos do objeto ainda podem ser alterados**, pois objetos em JavaScript são mutáveis. 
>
> Esse comportamento é definido pela especificação da linguagem e é fundamental para o uso correto de `const` no dia a dia.

<br />

## <img src="https://i.imgur.com/zCTwZAz.png" title="source: imgur.com" width="3%"/>**Exemplo 05 - Declaração de  Constantes**

```javascript

usuario.nome = "João da Silva Junior";
console.log("O Nome do Usuário é: ", usuario.nome);
```

<img src="https://i.imgur.com/V2ReOnx.png" title="source: imgur.com" width="3%"/>**Resultado do Código:**


Observe que o objeto `usuario` **sempre aponta para a mesma referência na memória**, pois foi declarado como **`const`**. No entanto, **as propriedades internas do objeto podem ser modificadas**, já que objetos em JavaScript são mutáveis.

Fazendo uma analogia com linguagens orientadas a objetos como **Java** ou **C#**, a instrução `usuario.nome = valor` é conceitualmente equivalente à chamada de um método *setter*, como por exemplo: `usuario.setNome(valor)`.

Agora, vamos refazer o exemplo tentando **reatribuir um novo objeto** à constante `usuario`:

## <img src="https://i.imgur.com/zCTwZAz.png" title="source: imgur.com" width="3%"/>**Exemplo 06. - Declaração de  Constantes**

```javascript
const usuario = { nome: "João da Silva" };

```

<img src="https://i.imgur.com/V2ReOnx.png" title="source: imgur.com" width="3%"/>**Resultado do Código:**

Nesse caso, o JavaScript retorna um **erro em tempo de execução**, indicando que **não é permitido reatribuir um valor a uma constante**. Isso ocorre porque `const` impede a alteração da **referência**, ainda que o valor seja de mesmo tipo ou estrutura.

> ### Resumo assertivo:
>
> - `const` **não permite reatribuição do identificador**.
> - Para **tipos primitivos**, o valor realmente não pode ser alterado.
> - Para **objetos e arrays**, a referência é fixa, mas **seus dados internos podem ser modificados**.

Esse comportamento torna o uso de `const` uma **boa prática padrão** em JavaScript moderno, pois aumenta a previsibilidade do código e reduz erros relacionados à reatribuição indevida de valores.

<h2>3. Entrada e Saída de dados</h2>



No JavaScript, existe um **método nativo** responsável pela **saída de dados em tela**:

- **`console.log()`**

Já em relação à **entrada de dados via teclado**, o JavaScript **não possui um método nativo genérico**, pois a linguagem foi criada originalmente para ser executada dentro de **páginas HTML**. Dessa forma, a entrada de dados sempre esteve associada aos **elementos da própria linguagem HTML**, como `input`, `textarea` entre outros componentes utilizados na construção de formulários.

Além disso, os **navegadores web** fornecem API's específicas para entrada e saída de dados, assim como ambientes de execução como o **Node.js**, que disponibilizam mecanismos próprios para esse fim.

<br />

<h3>3.1. console.log()</h3>



O método **`console.log()`** é utilizado para **exibir dados no console**, sendo considerado um **método de saída de dados**. Ele escreve informações no **dispositivo padrão de saída**, que pode ser o **console do navegador** ou o **terminal**, dependendo do ambiente de execução.

Esse método é amplamente utilizado durante o desenvolvimento **frontend e backend**, pois permite acompanhar, em tempo real, o estado das variáveis, o fluxo de execução do código e o resultado de expressões, auxiliando diretamente no processo de depuração.

**Sintaxe:**

```javascript
console.log("texto");

console.log(variavel);

console.log("texto" + variavel);
```

Note que é possível exibir apenas um texto, apenas o valor de uma variável ou **combinar texto e variáveis** utilizando o operador de concatenação (`+`). Nesse caso, o texto deve estar sempre delimitado por aspas.

<br />

> [!TIP]
>
> O comando **`console.log()`** é uma ferramenta fundamental para **debugar (depurar)** código JavaScript. Ele permite exibir **mensagens, valores de variáveis e resultados de expressões** no console, facilitando a identificação de erros, a análise do comportamento do programa e a compreensão do fluxo de execução da aplicação.

<h2>4. Operadores</h2>



Os **operadores** são símbolos especiais utilizados para realizar operações sobre valores e variáveis. No JavaScript, eles permitem executar cálculos, comparar valores, atribuir dados e trabalhar com expressões lógicas.

<br />

<h3>4.1. Operadores Aritméticos</h3>



Os operadores aritméticos são utilizados para realizar **operações matemáticas básicas**.

| Operador | Operação                  |
| -------- | ------------------------- |
| `+`      | Soma                      |
| `-`      | Subtração                 |
| `*`      | Multiplicação             |
| `/`      | Divisão                   |
| `%`      | Módulo (resto da divisão) |

<h4>4.2.1. Template Strings (Template Literals)</h4>



Uma forma moderna e mais legível de concatenar **strings**, **variáveis** e até **expressões matemáticas** é utilizando as **Template Strings**.

As Template Strings permitem **interpolar expressões diretamente dentro do texto**, usando a sintaxe `${expressão}`. Para isso, o conteúdo deve ser delimitado por **crases** (```), e não por aspas simples ou duplas.

**Sintaxe:**

```js
`Início do texto ${variavel} texto ${variavel_01 + variavel_02} fim do texto`
```

#### Observações importantes

- O **acento grave (`)** indica que a string permite interpolação.
- As expressões interpoladas devem estar entre **`${ }`**.
- Dentro das chaves é possível usar variáveis, expressões e operações matemáticas.

```js
/* Criar as variável */
let nome = "Sabrina";

/* Concatenação de strings */
```

<h3>4.5. Operadores Relacionais</h3>



Os operadores relacionais são usados para **comparar valores**, retornando sempre um valor booleano (`true` ou `false`).

| Operador | Descrição              |
| -------- | ---------------------- |
| `>`      | Maior que              |
| `>=`     | Maior ou igual         |
| `<`      | Menor que              |
| `<=`     | Menor ou igual         |
| `==`     | Igual                  |
| `!=`     | Diferente              |
| `===`    | Estritamente igual     |
| `!==`    | Estritamente diferente |

<br />

> [!WARNING]
>
> Não confunda **operadores relacionais** com o **operador de atribuição (`=`)**:
>
> - `=` → atribui valor
> - `==` e `===` → comparam valores
>
> ### Igual (`==`) vs Estritamente igual (`===`)
>
> - **`==`** realiza **conversão automática de tipos** (*coerção*).
> - **`===`** compara **valor e tipo**, sendo mais seguro e previsível.
>
> **Boa prática:**
>  Prefira sempre **`===`** e **`!==`**.

<br />

## <img src="https://i.imgur.com/zCTwZAz.png" title="source: imgur.com" width="3%"/>**Exemplo 08 - Igual vs Estritamente Igual**

```js
/* Criar as variáveis */
let numero = 10;
let texto = "10";

/* Comparação com igualdade (==) */
console.log(numero == texto);

/* Comparação com igualdade estrita (===) */
console.log(numero === texto);

```

<img src="https://i.imgur.com/V2ReOnx.png" title="source: imgur.com" width="3%"/>**Resultado do Código:**

```bash
true
false
```

Na comparação utilizando o operador **`==`**, o JavaScript realiza a **conversão automática de tipos** (*coerção*), fazendo com que o valor numérico `10` seja considerado igual à string `"10"`.

Já na comparação com o operador **`===`**, o JavaScript compara **valor e tipo ao mesmo tempo**. Como um é do tipo `number` e o outro do tipo `string`, o resultado da comparação é `false`.

Embora ambos os operadores realizem comparações, o uso do **`===`** é considerado **mais seguro e previsível**, sendo a **boa prática recomendada** em JavaScript.

<h2>5. Estruturas Condicionais</h2>



As **estruturas condicionais** permitem que o programa **tome decisões** com base em condições lógicas, executando diferentes blocos de código conforme o resultado dessas condições.

No JavaScript, existem **quatro estruturas condicionais básicas**:

1. **Estrutura `if`**
2. **Estrutura `if / else`**
3. **Estrutura `if / else if / else`**
4. **Estrutura `switch case`**

<br />

<h3>5.1. O Laço Condicional IF</h3>



A estrutura `if` executa um bloco de código **apenas se a condição for verdadeira (`true`)**.

**Sintaxe:**

```java
if(condição){
	// Executa alguma ação caso a condição seja verdadeira
}
```

<br />

<h3>5.2. O Laço Condicional IF/ELSE</h3>



A estrutura `if / else` permite definir um **fluxo alternativo**, executando um bloco quando a condição for verdadeira e outro quando for falsa.

**Sintaxe:**

```java
if(condição){
    // Executa alguma ação caso a condição seja verdadeira
}else{
    // Executa alguma ação caso a condição anterior anterior seja falsa
}
```

<br />

<h3>5.3. O Laço Condicional IF/ELSE IF / ELSE</h3>



Essa estrutura é utilizada quando há **mais de uma condição a ser avaliada**, sendo testadas em sequência até que uma delas seja verdadeira.

**Sintaxe:**

```javascript
if(condição 1){
    // Executa alguma ação caso a condição seja verdadeira
}else if (condição 2){
    // Executa alguma ação caso a condição anterior seja falsa
}else if (condição N){
    // Executa alguma ação caso as condições anteriores sejam falsas
}else{
    // Executa alguma ação caso todas as condições anteriores sejam falsas
}
```

<br />

<h3>5.4. Laço Condicional SWITCH CASE</h3>



A estrutura `switch case` é indicada quando se deseja comparar **um mesmo valor com múltiplas possibilidades**, tornando o código mais organizado e legível do que vários `else if`.

**Sintaxe:**

```java
switch(variável ou valor){
    case valor1:
        // Executa alguma ação caso esta condição seja verdadeira
        break;
    case valor2:
        // Executa alguma ação caso esta condição seja verdadeira
        break;
    case valorN:
        // Executa alguma ação caso esta condição seja verdadeira
        break;
    default:
        // Opcional -  Executa alguma ação caso todas as condições acima forem falsas
}
```

O uso do `break` é fundamental para evitar que o código continue executando os próximos casos (*fall-through*).

<br />

O **Operador Condicional Ternário (`? :`)** é uma forma **simplificada** de escrever uma estrutura `if / else` simples. Ele avalia uma condição booleana e retorna um valor conforme o resultado dessa avaliação.

**Sintaxe:**

```javascript
condição ? expressão_01 : expressão_02
```

**Onde:**

- **condição:** Expressão booleana a ser avaliada.
- **expressão1:** Executada caso a condição seja `true`.
- **expressão2:** Executada caso a condição seja `false`.

**Observações importantes:**

- É possível utilizar **mais de uma condição**, assim como no `if` tradicional;
- Embora seja permitido **encadear operadores ternários**, essa prática **não é recomendada**, pois pode comprometer a legibilidade e a manutenção do código.

<br />

<h2>6. Laços de Repetição</h2>



Os **laços de repetição** (ou *loops*) permitem executar um mesmo bloco de código **várias vezes**, enquanto uma condição lógica for satisfeita. Eles são amplamente utilizados para percorrer listas, repetir cálculos e automatizar tarefas repetitivas.

Na linguagem **JavaScript**, existem **três laços de repetição básicos**:

1. **`for`**
2. **`while`**
3. **`do...while`**

<br />

<h3>6.1. O Laço de Repetição FOR</h3>



O laço `for` é indicado quando se **conhece previamente a quantidade de repetições** que será executada.

**Sintaxe:**

```java
for(valor inicial; condição limite ou teste; contador){
    // Bloco de comandos (corpo do laço de repetição)
}
```

**Onde:**

1. **Valor inicial:** geralmente é uma variável numérica inicializada (ex.: `let i = 0`).
2. **Condição limite:** expressão lógica que determina até quando o laço será executado.
3. **Contador:** responsável por atualizar o valor da variável a cada iteração.

**Exemplos comuns de contador:**

- **Incremento (`++`)**: utilizado quando o valor inicial começa em um número menor e cresce até o limite.
- **Decremento (`--`)**: utilizado quando o valor inicial começa em um número maior e diminui até o limite.

<br />

> [!WARNING]
>
> Embora o uso das chaves `{ }` seja opcional quando há apenas uma instrução, **boas práticas recomendam sempre utilizá-las**, pois os laços de repetição geralmente possuem mais de um comando em seu corpo, o que melhora a legibilidade e evita erros.

<br />

<h3>6.2. O Laço de Repetição WHILE</h3>



O laço `while` executa um bloco de código **enquanto uma condição booleana for verdadeira**. Ele pode ser entendido como um `if` que se repete continuamente.

**Sintaxe:**

**Sintaxe:**

```java
while(condição limite){
     // Bloco de comandos (corpo do laço de repetição)
}
```

Diferentemente do `for`, o `while` **possui apenas a condição de parada**, sendo necessário controlar manualmente a variável de repetição dentro do bloco.

Esse laço é indicado quando **não se sabe exatamente quantas vezes o código deverá ser executado**, mas se conhece a condição que encerra o loop.

<br />

> [!WARNING]
>
> Assim como nos outros laços, recomenda-se o uso das chaves `{ }` mesmo para um único comando, garantindo maior clareza e manutenção do código.

<br />

<h3>6.3. O Laço de Repetição DO... WHILE</h3>



O laço `do...while` possui uma estrutura diferente dos demais, pois a **condição é avaliada somente após a execução do bloco de comandos**. Por esse motivo, ele é conhecido como um laço **controlado pela saída**.

**Sintaxe:**

```java
do{
     // Bloco de comandos (corpo do laço de repetição)
} while (condição limite);
```

A principal característica desse laço é que o **bloco de comandos será executado pelo menos uma vez**, independentemente do resultado da condição.

Esse comportamento é útil em situações onde o código precisa ser executado ao menos uma vez, como menus interativos ou validações iniciais.

<br />

> [!WARNING]
>
> Assim como nos demais laços de repetição, o uso das chaves `{ }` é recomendado para manter o código organizado e evitar ambiguidades.
